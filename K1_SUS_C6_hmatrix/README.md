# K1_SUS_C6_hmatrix — near direct / far ACA

170 GHz、C6全6モード、SUS表面インピーダンスを維持した独立版です。
K1_SUS_C6_geometry_opt の解析的可視性判定と候補除外を引き継ぎます。
既存の K1_SUS_C6 / K1_SUS_C6_geometry_opt と保存結果は変更していません。

**状態：実装と小メッシュの検証は完了。本番での高速化・物理的収束・
メッシュ収束は未確認です。現時点で本番用の高速ソルバーとしては推奨しません。**

## 実装

- パネル重心を空間的に二分し、テーパと直管を別々のクラスタ木にします。
- 相対セクタ d=0,…,5 の各作用素ブロックを構築します。
  6モードごとに別の作用素を構築する方式ではありません。
- 近傍・圧縮不適合ブロックは既存 Fortran の pair_map_local で直接計算します。
  近傍ブロックはFortranでまとめて処理し、スレッドごとに異なる観測先を担当します。
- 遠方候補は部分ピボットACAで A ≈ U V に圧縮します。
  複素行列の積は U V であり、Vの共役転置ではありません。
- 全要素を小分けに評価し、ブロックごとに
  ||A-UV||F ≤ hm_tol ||A||F を確認してから採用します。
  ACAの少数サンプルだけでゼロや収束とは判定しません。
- 許容誤差、最大ランク、保存効率の条件を満たさなければ細分化し、
  最小クラスタでは直接計算に戻します。
- 圧縮ブロックがゼロなら、既存の直接C6作用素をそのまま呼びます。
- モードへの作用は Σd exp(+2π i m d/6) Ad を使います。
  入出力は従来どおりセクタ局所座標の電流です。
- 189観測点の電場は引き続き既存ワーカーの直接放射積分で計算します。

物理核は再実装していません。有限導電率、等価磁流、近接項、
表裏判定、幾何学的遮蔽は参照元と同じです。
距離cutoff、ビームcutoff、反射次数による任意の減衰はありません。
今回の追加誤差はH行列の代数的圧縮誤差です。

## 計算量と精度の意味

全要素の残差検証を採用したため、**初回構築は O(Q²) または、
不成立ブロックの再分割によりそれ以上になり得ます。**
初回構築から二乗計算量を解消するMLFMA実装ではありません。

再利用時は、近傍の直接ペア数に加え、
遠方の Σ rank × (行数+列数) に対応する演算が必要です。
高周波でランクが増大したり直接ブロックが多く残った場合は、
全体がほぼ二乗のままになり、高速化できません。

ブロックごとのFrobenius誤差は、累積電流・観測電場の相対誤差を
直接保証しません。打ち消し合いや反復による増幅があります。
直接C6との比較、圧縮許容値を厳しくした比較、次数・メッシュ収束を
別々に確認してください。幾何・PO・一点積分の物理的精度も別問題です。

## ビルドと小規模検証

このディレクトリで実行します。Pythonは ../.venv/bin/python です。
追加Python依存はNumPyのみです。Fortran/OpenMP共有ライブラリを使います。

    make
    make test

小メッシュでの保存・再開の例：

    OMP_NUM_THREADS=2 OPENBLAS_NUM_THREADS=1 ../.venv/bin/python run.py --config config_smoke.nml --operator hmatrix --output results/hm_smoke --max-order 3 --steps 2

同じコマンドを再実行すると、保存済み次数の次から再開します。
config_smoke は物理的な結果を得るためのメッシュではありません。
比較スクリプトは512パネル／セクタ、0～3次のみを使います。

    OMP_NUM_THREADS=2 OPENBLAS_NUM_THREADS=1 ../.venv/bin/python benchmark_hmatrix.py

本番メッシュでのH行列構築も重い計算です。本番は実行していません。

## 設定

|引数|既定値|意味|
|---|---:|---|
|--operator|direct|direct または hmatrix。H行列は明示選択|
|--hm-tol|1e-6|各採用ブロックの相対Frobenius残差上限|
|--hm-leaf|16|最小クラスタのパネル数目安|
|--hm-max-rank|32|ACAの最大ランク|
|--hm-eta|2|最大クラスタ径 ≤ eta × 箱間距離|
|--hm-phase-limit|8|k × 径T × 径S ≤ phase_limit × 箱間距離|
|--hm-memory-mib|512|因子・ブロック・近傍索引のキャッシュ予算|

最後の予算はプロセス全体のRAM上限ではありません。
Fortranの形状、電流、Pythonの木、検証用一時配列は追加で必要です。
予算超過・20万ブロック超過ではエラー終了し、前次数を保持します。
遠方候補の条件は圧縮を試すかどうかだけを決め、寄与を切り捨てません。
デフォルトより緩い候補条件でも全要素の残差検証は省略しません。

## 保存と中断

- 反射次数の state.npz / meta.json、atomic rename、fsync、出力先ロック、
  STOPマーカーの仕組みは従来どおりです。
- 完成した作用素を出力先内の hm_cache に保存し、別起動でも再利用します。
- 設定、ソース、実行ファイル、共有ライブラリ、圧縮設定が変わると
  同じ出力先への再開を拒否します。旧版の保存結果は流用できません。
- キャッシュにはSHA-256を付け、破損・指紋違い・構造不整合を拒否します。
- 0次はH行列構築前に保存されます。構築中に失敗しても保存済み次数は残ります。
- **H行列の構築途中からの再開は未対応**です。未完成キャッシュは再構築します。
- Ctrl+C/SIGTERMのPython処理は実行中のネイティブ呼び出しが戻るまで
  遅れる場合があります。強制終了でも最後の確定済み次数は保持されます。
  STOPは現在の次数を保存した後、次の次数に入る前に処理します。
- Fortran共有ライブラリは1プロセス1形状です。異なるKernelを同時使用する
  Python APIではありません。置換後の古いKernelの呼び出しは拒否します。

## 検証結果（2026-09-09）

make test の12項目が通過しました。

- 複素低ランク行列のACA復元、サンプル外の欠陥を全要素検証で検出。
- 実際のSUS/C6作用素で圧縮と直接フォールバックが両方動くこと。
- 任意の複素電流・全6モードの直接C6比較。
- 完成キャッシュ再利用、破損・設定変更・メタデータ不整合の拒否。
- 連続実行と中断再開で次数電流・累積電流・電場が一致。
- 既存の7項目の保存・再開管理テスト。

512パネル／セクタ、2スレッド、leaf=8、eta=3、phase_limit=24、
max_rank=32での結果：

|圧縮許容値|採用低ランクブロック|構築・保存等|3次の累積電流相対差|3次の累積電場相対差|
|---|---:|---:|---:|---:|
|1e-3|581|47.4秒|2.53e-5|2.71e-5|
|1e-5|484|54.9秒|4.94e-8|6.00e-8|

1e-5では、連続する3次数のワーカー時間は直接計算0.344～0.357秒、
H行列＋直接電場計算0.343～0.361秒でした。**実質同程度です。**
初回構築を含めると、この規模・次数ではH行列版が遅くなります。
これは本番速度の予測ではなく、少数回の小メッシュ測定です。
本番で高速化する、あるいは物理的に正しい結果になるという証拠ではありません。

benchmark_results.json が最終版の測定値です。
benchmark_conservative_results.json は初期の保守的候補条件で圧縮ゼロだった
記録で、近傍一括化・圧縮ゼロ時の直接C6フォールバック追加前の測定です。
test.log に最終テスト結果を保存します。

## ファイルと背景資料

- hmatrix.py：空間分割、ACA、残差検証、C6作用、キャッシュ。
- acceleration/mod_bridge.f90：既存Fortran作用素への接続・近傍一括計算。
- run.py：方式選択と反射次数の保存・再開。
- baseline_manifest.json：参照元ファイルのSHA-256。
- GEOMETRY_BASELINE.md：前段の幾何最適化の説明。

ACAとブロッククラスタ構築の背景：
[HLIBpro: Integral Equation](https://hlibpro.com/doc/3.0/TUTORIntEq.html)、
[HLIBpro: Block Cluster Tree](https://www.hlibpro.com/doc/2.5/TUTORBCT.html)。
後者は高周波のHelmholtz/Maxwell作用素でランク増大が問題になることを説明しています。
本実装はHLIBproを利用したものではなく、既存IPO作用素に対する独立実装です。
